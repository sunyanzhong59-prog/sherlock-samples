# Calibration —— 拿有标准答案的靶，量一个审计流程的真实错误率

> **English abstract.** This directory is an auditor's calibration harness. Thirty
> exercises were run against publicly available Sherlock judging repositories; every
> finding was written and hashed *before* the answer key was opened, then reconciled
> against the official judgement. The scorecards below report the resulting error
> rates — **including the author's own systematic failures**. All cases here are
> *post-hoc, independent reproductions* of publicly disclosed contest results, not
> contest submissions by the author.
>
> Four failure directions are catalogued: **under-grading**, **severity merging**,
> **false positives**, and — added by CASE-04 — **answer-key deference**, i.e. cases
> where a *correct, code-proven* disproof of the author's was overturned merely because
> the official judgement disagreed, with the error documented byte-for-byte against
> upstream OpenZeppelin v4.9.6 source (`sha256 82789e6b…`). The answer key is treated
> here as **a judgement, not as ground truth** — and is itself audited.

---

## 0. 这不是什么

先说清边界，免得被误读：

| 不是 | 是 |
|---|---|
| ❌ 我在 Sherlock 比赛里提交过的 finding | ✅ 比赛结束、判罚仓公开之后，我做的**事后独立复现** |
| ❌ "我发现了这些漏洞"式的战绩宣称 | ✅ "我能否独立走到官方结论"的**能力测量**，含大量失败 |
| ❌ 全新的 0day | ✅ 已修复的历史漏洞 + 官方答案，用作**训练/评估的 ground truth** |
| ❌ 一份漂亮的简历 | ✅ 一份带错误率的成绩单 |

**为什么必须这么声明**：一份"我发现了 X"的 writeup，只要有人去查比赛 Watson 名单就会发现作者不在其中 —— 这种失真是负资产。而"我用公开答案键量化了自己的错误率"是**可核查**的，而且几乎没人公开做。

## 1. 为什么需要校准

漏洞赏金/审计竞赛的门槛不是钱，而是**信用的不可逆性**。以 Sherlock 竞赛为例：

```
Issues Ratio = valid issues / total issues submitted  ≥ 20%
```

每一条误报都在**永久拉低分母**，且这个比率写在公开 profile 上。所以进场前必须先回答两个问题：

1. 我能否**稳定**地独立找到 Medium 及以上的根因？
2. 我**会不会**误报？

这两个问题**无法自我回答** —— 自己给自己出题不算数，读完代码觉得"懂了"也不算数。唯一能测出来的方式：在**有外部标准答案的真实靶**上盲测。

## 2. 方法：三段式盲测

```
① 建靶封笔        ② 开封对账              ③ 成绩单落盘
   ├ 读 scope 源码    ├ 解封官方判罚仓         ├ 五项指标逐条计数
   ├ 写 _FINDINGS.md  ├ 我的每条 ↔ 官方条目     ├ 失败归因到"规则缺失"层
   ├ 记录观察区/否证区  ├ 逐字对质（原文引用）      └ 增量写回方法论文档
   └ sha256 时间戳    └ 分清 valid / invalid
```

**关键纪律 —— 第 ① 步必须可证**：

- `_FINDINGS.md` 在开封前写定，落盘时打 **sha256 + 时间戳**，开封后不得修改正文（只能追加"对账"章节）。
- 观察区 / 否证区**必须显式写出**。理由见 §5.2：**"看见并否定"和"根本没看见"是两种完全不同的病**，只有写下来才能区分。
- 判级在封笔时自评，不与官方对照 —— 否则判级校准就失去意义。

**判罚仓布局是个真问题**。30 个靶里至少出现过 11 种不同的官方判罚仓布局，常见的坑：

- 家族目录（`NNN/`）与扁平根（`NNN.md`）**并存** —— 只读一边会漏掉 1/3 的 valid 条目。
- `invalid/` 目录里混装**两类东西**：实质性否定 + **重复项**（根因正确，只是被别人先交）。把后者当误报会得到相反结论。
- `invalid/NNN.md` 正文标注 High、但归属目录是 `invalid/` ⇒ **以目录归属为准**（此坑在 30 靶里命中 4 次）。
- `invalid/` 为空目录 ⇒ **该靶误报率不可测**，只能测召回。

## 3. 五个计分维度

| # | 维度 | 定义 | 为什么单独计 |
|---|---|---|---|
| 1 | **独立发现** | 我的主张命中官方 valid 根因的条数（dup 只记 1） | 召回侧主指标 |
| 2 | **误纳**（假阳性） | 我报了、但官方无同根因条目 | 直接决定 submission 风险 |
| 3 | **误剔**（假阴性） | 我**看见了**、写进观察区或否证区，但官方判 valid | ⚠️ 见下 |
| 4 | **判级一致性** | 我判的级别 vs 官方级别（分偏低/偏高计数） | 决定奖金档位 |
| 5 | **簇级漏族** | 我**完全没看见**的根因大类数 | 召回侧的结构性指标 |

### 为什么"误剔"比"误纳"更值得单独计

误纳是**噪声** —— 提交前能被双搜/自检拦下来，代价可控。

误剔是**能力上限**。一个"看见了但判断为无影响"的条目，意味着我的**影响评估**错了，而不是我的读码覆盖率错了。这类错误在赏金提交里表现为"我读到了这个函数，但没想到它可被利用" —— 而它恰恰是**唯一无法靠读更多代码来修复**的错误类型。30 靶中，误剔涉及的高危条目数长期高于误纳。

> 另一个常被忽略的坑：**分母不可加总**。各靶判罚仓口径差异极大（有的 666 条 valid，有的只有 6 条真 bug，有的 `invalid/` 为空）。所以本文**不计算"总命中率"** —— 那是个伪指标。只统计错误实例的分类分布，以及错误在靶序上有没有漂移。

**⇒ 结论**：四问全达标的靶数 = **0**。所以这条练兵路径在 #30 终止，转向真实靶 —— 以"平台 triage 是否收下"为唯一验收标准。**校准的价值不是让我变成一个不出错的审计员，而是让我知道自己会在哪一类事情上出错。**

## 5. 失败分类学

### 5.1 判级偏低（最顽固）

跨 3 个靶出现 **100% 全量偏低**（#22：14/14 全部低 1–2 档）。

**病根（第 4 次换新后定性）**：我的判级三问是「① 资金锁死？② 核心流程恒定 revert？③ 少赚/延迟？」——
**全部围绕"攻击者是外部人"建模**。当攻击者是 OPERATOR / SETTER / 治理角色时，三问**没有任何一档会跳到 High**，于是全部落 Medium/Low。

而竞赛平台的口径是：**"资金可被移出协议 / 背书守恒被破坏 / 供给调控失控 ⇒ High，不问金额、不问攻击者身份。"**

修复动作是加"第 0 问"（守恒问），但它**只在最显眼的那条上被认真执行**，其余条目照旧低报。见 §4.3。

### 5.2 误剔（看见并否定）

这是最贵的一类。典型形态：

- **拿"官方声明接受 / 出 scope / 在信任假设内 / 无实际影响 / 设计如此"当删除理由** —— 早期 6 靶里这类剔除共丢 **13 条官方根因，其中 High ≥12**。观察区实际上等于"不提交"。
- **依赖源码没读**：把 scope 内的 `lib/` 或基类当"第三方库"跳过 ⇒ 单靶丢 8 条（含 High×2）。
- **`invalid/` 口径混用**：把"根因正确但撞了 dup"当成自己误报。

### 5.3 误纳（唯一的误报样本）

#23 的 F2 是全期最干净的误报样本，值得完整记录（见 [`CASE-03`](CASE-03_morpho-false-positive.md)）：

我自己数值推演已经算出触发条件需要 `debt < supply × 1e-7`（**近清仓 + 特定市场参数 + decimals 组合**三重边缘条件），却仍保留 Medium 提交。官方没收。

**固化规则**：当 PoC 依赖"接近清仓 + 特定参数组合 + 精度假设"三重边缘条件时 ⇒ **落观察区，不提交**。"实际性"门槛比我原先理解的更严。

### 5.4 漏族（结构性）

反复出现的同型病灶：**"自建辅助表制造'我扫过了'的错觉"**。

我做了覆盖表、留痕表、六问表 —— 表填满了，于是产生"这一面已审"的心理确认，但**表里的问题本身可能提错了**。最典型的一个：

- 靶内出现一种准入限制（白名单）⇒ 我审了"被限制的那个函数"是否严密，
- **但没做横向表**：列出所有能到达同一效果的入口，逐个验证限制是否同样生效。

结果单靶漏掉 28+ 条同族条目（含多条 High）。

固化规则：**凡 scope 内出现一种准入限制（白名单 / NFT / 签名 / 角色），必须列出所有能到达同一效果的入口并逐个验证。**

### 5.5 级别合并（写这批文档时才发现的新病灶）

**这是本目录里第一条「我原先的成绩单漏记、在写 writeup 复查时才暴露」的错误**（第二条见 §5.6）。

`#30` 的 F3（EIP-712 跨函数重放）我自评 **High**，成绩单记为"判级准确"。但复查官方判罚仓时发现：**官方把同一个根因按后果强度拆成了两个级别** ——

| 官方条目 | 后果 | 级别 |
|---|---|---|
| `042 / 065 / 091 / 170 / 279 / 338 / 391` | 同一签名**被反复使用** ⇒ 余额被**持续扣走**、配置被回滚 | **High** |
| `105` | 跨函数重放 ⇒ **单次**非自愿付款 / 重复创建 agent | **Medium** |

我把这两条路径合并成了一个 High。后果是**双向失真**：既给 Medium 那部分判高了级，又让 High 那部分的论证偷偷依赖"可重复"这一前提却从没写出来。

**为什么这条以前没被发现**：我的对账表只有"条目级是否命中根因"和"判级是否偏低"两栏，**没有"一条主张是否对应官方的多条不同级别条目"这一栏**。所以合并错误在结构上无法被检测 —— 这不是判级不准，是**对账口径本身有缺口**。

> **固化规则（新）**：一个根因若同时产生**后果强度不同**的多条路径，必须**按后果分列**、各自判级，不能合并为一个 finding 取最高级。
> 判别标准：**资金是否离开受害者的控制范围** + **能否重复**。
> ——"留在他自己名下的资产里"与"流出到协议外且可重复"是两档，不是一档。

### 5.6 服从答案键（CASE-04 才发现 —— 唯一一个"更严格地对自己"修不好的病灶）

前五类都指向同一个方向：**我太宽松、我漏了、我判低了**。所以修法也都在同一个方向：更严格地对待自己。

**这一类反过来了。** `#22` 里我写下了对自己否证的完整推理与源码证据（`MasterAMO` 未调 `__ReentrancyGuard_init()` ⇒ 非漏洞），开封对账时看到官方判 **High**，就把结论改判成了「**我错了**」，还给它编了一句自我归因。

写 CASE-04 时回码复核 —— **那个自我归因是错的**。OZ v4.9.6 源码逐字（与上游**比特级一致**，`sha256 82789e6b…`）：

```solidity
35:    uint256 private constant _NOT_ENTERED = 1;
36:    uint256 private constant _ENTERED = 2;
38:    uint256 private _status;                            // 默认 0
63:    require(_status != _ENTERED, "ReentrancyGuard: reentrant call");
```

`__ReentrancyGuard_init()` 的全部作用是把 `_status` 从 `0` 改成 `1`；而守卫判定式是 `_status != 2`。
`0 != 2` 与 `1 != 2` 同为真 ⇒ **初始化与否不改变守卫的任何一次判定**。条目所称的
"complete loss of reentrancy protection" 在代码层不成立（另两条证据见 CASE-04 §6.2：6/6 外部入口均带 `nonReentrant`；该条目自己的前置条件就要求特权调用者 + 恶意池）。

**危害不是少赚钱，而是测出来的画像失真** —— 成绩单上写着「我误判 2 条」，实际是「我误判 1 条 + 2 条正确否证被冤枉」。
一个偏保守的错误率，会让我**在不该让步的地方让步**。赏金提交里等价的失效模式：证据已经站得住了，却因为"评委可能会觉得没影响"而把 finding 砍掉。

> **固化规则（新）**：**答案键不是地面真值。** 凡我**已用源码逐字或已执行 PoC** 否证过的条目，遭官方否定时：① 在成绩单里单独开一栏「我不同意」，写明代码证据；② 要求官方条目给出**代码层可验证的新证据**才能推翻我；③ 否则标记 **CONTESTED**，不得仅凭「官方判 High」就改判自己。
>
> **反向门槛（必须同时满足，否则本条会被滥用成自我辩护）**：该规则**只**适用于否证同时具备 **(a) 源码逐字引用（含精确 `file:line`）** 与 **(b) 可复现实证（PoC 执行 / 比特级比对 / grep 全树 0 命中）** 的情形。若否证建立在**推理 + 假设**上 ⇒ 官方优先级更高，照旧改判自己。
> 判别式一句话：**否证是「事实」还是「我觉得」？前者遭否时先怀疑官方；后者遭否时先怀疑自己。**
